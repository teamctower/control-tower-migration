# Control Tower Migration

A Node.js TypeScript project for parsing Android call logs and SMS logs from XML backup files and uploading them to the Control Tower API.

## Features

- Parse call logs from XML backup files
- Parse SMS logs from XML backup files
- Normalize data into consistent TypeScript interfaces
- Summary statistics for parsed data
- API authentication with JWT tokens
- Ready for API data upload

## Quick Start

1. **Install dependencies**:
   ```bash
   npm install
   ```

2. **Configure environment variables** (see Configuration section below)

3. **Add XML backup files** to `./data` folder:
   - `call logs.xml`
   - `SMS logs.xml`

4. **Run the migration**:
   ```bash
   npm run dev
   ```

## Configuration

**Important: Environment variables and XML backup files are required to run the application.**

### Step 1: Configure Environment Variables

1. Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```

2. Update `.env` with your API configuration:
```env
# API Base URL
API_BASE_URL=http://localhost:4000

# Your Control Tower credentials
API_USERNAME=your-email@example.com
API_PASSWORD=your-password

# Device name for this migration instance
API_DEVICE_NAME=your-device-name

# Device ID for data stream uploads
API_DEVICE_ID=your-device-id
```

3. **Security Note**: Never commit the `.env` file to version control. It's already included in `.gitignore` for your protection.

### Step 2: Add XML Backup Files

Place your Android backup XML files in the `./data` folder:

1. Create the `data` folder if it doesn't exist:
```bash
mkdir -p data
```

2. Copy your backup files to the data folder:
   - `call logs.xml` - Your Android call logs backup file
   - `SMS logs.xml` - Your Android SMS logs backup file

**Note**: These files are typically generated by Android backup apps like "SMS Backup & Restore". The files must be named exactly as shown above (case-sensitive).

**Flexibility**: The application can work with either file or both:
   - If only `call logs.xml` exists, it will process only call logs
   - If only `SMS logs.xml` exists, it will process only SMS logs
   - If both files exist, it will process both
   - If neither file exists, the application will complete with a warning and no data upload

## How It Works

The migration process follows these steps:

1. **Authentication**: Signs in to the Control Tower API using your credentials
2. **Parsing**: Reads and parses the XML backup files from the `./data` folder
3. **Normalization**: Converts the parsed data into a standardized format
4. **Upload**: Uploads phone activities to the API **one by one in chronological order** (oldest first)
   - Each record is uploaded individually with a 200ms delay between requests
   - Progress is displayed for each upload: `[1/88] ✓ incoming-sms - iyzico at 2022-12-05T12:08:11.259Z`
   - Failed records are tracked and displayed at the end

## Data Types

### Call Logs
- **Phone Number**: Contact phone number
- **Duration**: Call duration in seconds
- **Timestamp**: Unix timestamp
- **Call Type**: incoming, outgoing, missed, rejected, blocked
- **Contact Name**: Saved contact name
- **Readable Date**: Human-readable date string

### SMS Logs
- **Phone Number**: Sender/recipient phone number
- **Timestamp**: Unix timestamp
- **Message Type**: received, sent, draft, outbox, failed, queued
- **Body**: Message content
- **Contact Name**: Saved contact name
- **Readable Date**: Human-readable date string
- **Is Read**: Boolean flag

## API Integration

The parsed data is ready to be sent to an API. The data is normalized and available in the following format:

```typescript
{
  callLogs: NormalizedCallLog[],
  smsLogs: NormalizedSMSLog[],
  summary: {
    totalCalls: number,
    totalSMS: number,
    callsByType: { ... },
    smsByType: { ... }
  }
}
```

## API

### Authentication

The application uses JWT-based authentication with the Control Tower API.

#### Sign In API
- **Endpoint**: `POST /api/auth/signin`
- **Request Body**:
  ```json
  {
    "username": "user@example.com",
    "password": "password",
    "deviceName": "device-name"
  }
  ```
- **Response**:
  ```json
  {
    "statusCode": 201,
    "data": {
      "accessToken": "jwt-token",
      "refreshToken": "refresh-token",
      "user": {
        "userId": 24,
        "email": "user@example.com",
        "name": "User Name",
        "roles": ["admin", "control-tower-user"]
      }
    }
  }
  ```

### Usage Example

```typescript
import { signInApi } from './api';

// Sign in
const authData = await signInApi({
  username: 'user@example.com',
  password: 'password',
  deviceName: 'my-device'
});

// Access token is automatically stored and used for subsequent requests
console.log('User:', authData.user.name);
console.log('Roles:', authData.user.roles);
```
